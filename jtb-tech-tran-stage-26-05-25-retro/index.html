最終建議

1. 數據面仍支持換 Qwen-14B int4：298 case 雙第一（品質 +2 句、速度 4x），onesmart11~15 與 dev box 同款 5090（machines.yaml 確認），零硬體移植 risk。

2. 但部署前要先解 "locker" 問題：日語 ja-寄物櫃 場景 14B 100% 出 latin "locker"（連犯 3 次）。在切 production 前要：
    a. 改 prompt 加「外來語不保留 latin」或具體規則 ロッカー → 寄物櫃
    b. 或 ac_term 補規則 locker:寄物櫃
    c. 重跑 retro 確認沒退化

3. 切換策略建議：
    a. 不要全機隊一次換 — production 跑 TG 已穩、切換成本 ≠ 零
    b. 先 onesmart11 pilot（建議閒置時段、不影響旅客）
    c. 監控 latency p99 + 輸出長度分布（看會不會像 Aya 偶發幻覺）
    d. 保留 TG sidecar、用 feature flag 切（如果 14B 出包可秒回 TG）

4. 5/19 batch 上 TG 反而打贏 14B 1 句，提醒：14B 不是萬靈丹、各場景表現不一樣。要再蒐集 ko / vi / id 男性場景的更多錄音才有完整把握。
